# Module 5: Non-Relational Data Stores

## Introduction

Relational databases have been the default for decades, and for good reason. But some applications need flexible structures, extreme speed for simple lookups, or massive scale that a traditional relational design struggles to provide. In this module, we look at two common types of **NoSQL** stores, document and key-value, what they are good at, and how analysts work with the data they produce.

## Objectives

- Describe document stores and key-value stores and give examples of each.
- Compare non-relational stores with relational databases on structure, querying, and consistency.
- Decide when a relational database is the better choice and when a non-relational store fits.
- Explain how data from non-relational systems is brought into an analytics platform.
